# Goal 4: `dt run <script-name>` — Detailed Implementation Plan

## Overview

Goal 4 adds the `dt run` subcommand. It lets users execute any script previously
generated by `dt add` (stored in `~/.dt/scripts/`). Two invocation modes:

- **Named:** `dt run <script-name>` — runs the named script directly.
- **Interactive:** `dt run` (no args) — shows a fuzzy-searchable list of available
  scripts (with descriptions from their sidecar `.meta.json`), lets the user pick
  one, then executes it.

No new AI calls are made by this command. It is pure script discovery + execution.

#### 4. `test_discover_scripts_finds_sh_files`

```rust
#[test]
fn test_discover_scripts_finds_sh_files() {
    let dir = tempfile::tempdir().unwrap();
    std::fs::write(dir.path().join("foo.sh"), "#!/bin/bash\necho hi").unwrap();
    std::fs::write(dir.path().join("bar.sh"), "#!/bin/bash\necho bye").unwrap();
    // A non-script file that should be ignored
    std::fs::write(dir.path().join("foo.sh.meta.json"), r#"{"description":"d"}"#).unwrap();

    assert!(names.contains(&"foo.sh"));
    assert!(names.contains(&"bar.sh"));
    assert_eq!(entries.len(), 2, "meta.json sidecars must not appear as script entries");
}
```

**Why:** Meta files must be filtered out of the list. Only `.sh` and `.js` files
(or more generally: executable/non-`.meta.json` files) should appear.

## Phase 1 — Implement `src/commands/run.rs`

### Data types

```rust
/// One entry in the scripts directory.
pub struct ScriptEntry {
    pub filename: String,
    pub description: Option<String>,
}

impl ScriptEntry {
    /// Label shown in the FuzzySelect list: "filename  —  description"
    pub fn display_label(&self) -> String {
        match &self.description {
            Some(d) => format!("{}  —  {}", self.filename, d),
            None    => self.filename.clone(),
        }
    }
}

/// Sidecar JSON shape (mirrors ScriptMeta in add.rs).
#[derive(Deserialize)]
struct ScriptMeta {
    description: String,
}
```

---

### `discover_scripts(dir: &Path) -> Result<Vec<ScriptEntry>>`

```
1. Read the directory entries from `dir`.
2. For each entry:
   a. Skip if the filename ends with `.meta.json`.
   b. Attempt to read the corresponding `<filename>.meta.json` sidecar.
      - If present and parseable: set description = Some(value).
      - Otherwise: description = None.
   c. Push a ScriptEntry.
3. Sort entries by filename (deterministic order in the UI).
4. Return the vec.
```

Key detail: filtering on `.meta.json` suffix (not on file extension) keeps the
function generic — it will also pick up `.js` scripts and any future extensions
without changes.

---

### `resolve_script(dir: &Path, name: &str) -> Result<PathBuf>`

```
1. Construct `path = dir.join(name)`.
2. If `path.exists()`: return Ok(path).
3. Otherwise: return Err(anyhow!("Script '{}' not found in {}", name, dir.display())).
```

---

### `pub fn execute(script_name: Option<String>) -> Result<()>`

```
1. Resolve scripts dir via add::resolve_scripts_dir() (reuses existing helper).
2. If script_name is Some(name):
   a. Call resolve_script(&scripts_dir, &name)? to get the path.
   b. Jump to step 4.
3. If script_name is None:
   a. Call discover_scripts(&scripts_dir)?.
   b. If the list is empty: return Err("No scripts found in ~/.dt/scripts/. Run `dt add` first.").
   c. Build display labels from entry.display_label().
   d. Show dialoguer::FuzzySelect with the labels.
   e. Get the selected ScriptEntry; resolve its path via scripts_dir.join(&entry.filename).
4. Spawn the script via std::process::Command::new(&path).status()
   with stdio inherited.
5. Propagate the exit status: if !status.success(), return Err("Script exited with non-zero status").
```

## Key Design Decisions

| Decision | Rationale |
|---|---|
| Reuse `add::resolve_scripts_dir()` | Single source of truth for `~/.dt/scripts/`. Avoids duplicating the path constant. |
| Filter on `.meta.json` suffix (not file extension) | Future-proofs the discovery for `.js`, `.py`, or any other generated script type without code changes. |
| `description: None` for scripts without a sidecar | Manually placed scripts are first-class citizens. No error, just no description in the list. |
| `FuzzySelect` from `dialoguer` (already a dependency) | Consistent with the interactive pattern in `fixup.rs`. Zero new dependencies for the interactive UI. |
| `clap_complete` added but completion generation deferred | The PLAN.md specifies it as a new dependency for this goal; adding it now keeps the crate graph accurate without blocking the MVP. |
| Inherit stdio in `Command::new(&path).status()` | The script runs as if the user typed it directly — stdin/stdout/stderr all pass through. |
| Non-zero script exit → `dt run` also exits non-zero | Makes `dt run` composable in shell pipelines and CI scripts. |
